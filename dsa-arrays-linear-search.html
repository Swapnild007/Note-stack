Find an element without guessing

An array stores an ordered collection of values. Linear search checks those values one by one until it finds a match or reaches the end. Let's make every comparison visible.

What is an array?

Think of numbered compartments in a shelf. Each compartment has a position called an index. In many programming languages, the first element has index 0. The value is what you store; the index tells you where to find it.

Why do we care about time complexity?

Time complexity describes how the amount of work grows with input size. Linear search may find the target immediately, but in the worst case it must check every element. For an array containing n elements, that means up to n comparisons.

Best caseFirst element matchesO(1)
Average caseWork grows with input sizeO(n)
Worst caseLast element or missing targetO(n)

Original NoteStack concept diagram: linear search has constant best-case work and linear worst-case work.

Linear search does not need the array to be sorted. That simplicity is useful, although a different algorithm may be faster when the data has additional structure.

Translate the animation into code

The loop below follows the exact same steps as the interactive explorer. It compares each element with the target and returns its index when it finds a match. If no match exists, it returns -1.

function linearSearch(values, target) {
  for (let index = 0; index < values.length; index++) {
    if (values[index] === target) {
      return index;
    }
  }
  return -1;
}

console.log(linearSearch([4, 9, 2, 7, 1, 6], 7)); // 3
